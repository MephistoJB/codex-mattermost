# Настройка

[English version](SETUP.md)

Плагин запускает собственный локальный MCP-процесс и напрямую вызывает Mattermost REST API v4. Он рассчитан на Mattermost 10.11 и не требует прав администратора, плагина Mattermost Agents, внешнего MCP endpoint или извлечения cookie из браузера.

## 1. Установите плагин

Из GitHub:

```text
codex plugin marketplace add shanginn/codex-mattermost --ref main
codex plugin add mattermost-workflows@personal
```

Для разработки из существующего клона:

```text
codex plugin marketplace add /absolute/path/to/codex-mattermost
codex plugin add mattermost-workflows@personal
```

После установки или обновления начните новую задачу Codex.

## 2. Настройте авторизацию в macOS

Запустите утилиту из клона этого репозитория. Рекомендуемый способ входит как обычный пользователь Mattermost, получает обычный session token и сохраняет его в macOS Keychain:

```text
node plugins/mattermost-workflows/scripts/configure-macos.mjs \
  --server-url https://chat.example.com \
  --login-id YOUR_LOGIN
```

Введите пароль Mattermost по запросу. Он используется только в запросе входа, не выводится, не сохраняется и не попадает в аргументы команды. Если требуется MFA, утилита запросит текущий код. Полученный session token сохраняется в Keychain как generic password с сервисом `codex-mattermost`.

Утилита также создаёт `~/.config/codex-mattermost/config.json` с правами `0600`. Файл содержит только URL сервера и параметры поиска в Keychain:

```json
{
  "serverUrl": "https://chat.example.com",
  "auth": {
    "type": "macos-keychain",
    "service": "codex-mattermost",
    "account": "chat.example.com"
  }
}
```

Не копируйте этот локальный файл в репозиторий, хотя самого токена в нём нет.

### Использование существующего токена

Если у учётной записи уже есть personal access token или session token, передайте его через стандартный ввод, чтобы значение не попало в историю shell:

```text
read -r -s "MM_TOKEN?Mattermost token: "; printf '\n'
printf '%s' "$MM_TOKEN" | node plugins/mattermost-workflows/scripts/configure-macos.mjs \
  --server-url https://chat.example.com \
  --token-stdin
unset MM_TOKEN
```

Не помещайте токен в аргумент команды, файл проекта, issue или запрос чата.

## 3. Альтернатива через переменные окружения

MCP-сервер сначала проверяет следующие переменные:

```text
MATTERMOST_URL=https://chat.example.com
MATTERMOST_TOKEN=your-session-or-personal-access-token
```

Используйте этот способ, только если процесс Codex получает защищённое окружение. Не сохраняйте значения в `.env` внутри репозитория. Если переменных нет, сервер использует локальную конфигурацию и Keychain из предыдущего раздела.

## 4. Безопасная проверка

Откройте новую задачу Codex и начните с read-only запросов:

1. «Используй Mattermost Workflows и скажи, под какой учётной записью выполнено подключение».
2. «Покажи команды Mattermost, к которым у меня есть доступ».
3. «Определи указанный мной канал, но пока не читай сообщения».
4. «Прочитай последние пять сообщений и укажи их post ID».
5. «Подготовь ответ в одну строку, но не публикуй».

Для записи workflow сначала вызывает `prepare_post`, показывает точную зафиксированную цель и текст и запрашивает явное подтверждение. Только после этого разрешён вызов `create_post` с короткоживущим токеном подтверждения. Любое изменение текста или цели требует новой подготовки и подтверждения.

## Приоритет конфигурации

1. `MATTERMOST_URL` и `MATTERMOST_TOKEN`, если заданы обе переменные.
2. `CODEX_MATTERMOST_CONFIG`, если указывает на другой локальный JSON-файл.
3. `~/.config/codex-mattermost/config.json` и связанная запись Keychain.

Для нелокального сервера обязателен HTTPS. URL со встроенными учётными данными, query string или fragment отклоняется.

## Отзыв или замена доступа

- Для замены подключения повторно запустите утилиту: она обновит соответствующую запись Keychain.
- Чтобы удалить локальную конфигурацию, удалите `~/.config/codex-mattermost/config.json`.
- Чтобы удалить сохранённый токен, удалите generic-password запись `codex-mattermost` в Keychain Access.
- Администратор или владелец учётной записи может отдельно отозвать активные сессии или personal access tokens в Mattermost.

## Решение проблем

- **Нет инструментов Mattermost:** начните новую задачу после установки, затем проверьте, что плагин включён и его локальный MCP запускается.
- **Нет конфигурации:** запустите утилиту или задайте обе переменные окружения. Одного URL недостаточно.
- **Вход отклонён:** проверьте логин и пароль. В некоторых организациях API-вход отключён или обязателен SSO; тогда используйте разрешённый существующий токен через `--token-stdin`.
- **Нет доступа к каналу:** у подключённой учётной записи нет прав. Плагин не обходит ограничения.
- **Сессия истекла:** снова запустите утилиту для создания и сохранения новой сессии.
- **Публикация отклонена:** снова подготовьте черновик. Токены подтверждения действуют десять минут и используются один раз.

Перед отправкой отчёта об ошибке удалите или замените URL сервера, названия команд и каналов, содержимое сообщений, user ID и все учётные данные.
