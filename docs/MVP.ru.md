# Границы MVP

[English version](MVP.md)

## Цель

Дать Codex предсказуемый и проверяемый workflow для типовых задач в Mattermost без прокси-сервиса и хранения учётных данных Mattermost.

## Входит в MVP

1. **Сводка канала или треда** через `read_channel` или `read_post`.
2. **Ограниченный поиск сообщений** через `search_posts` с фильтрами команды и канала.
3. **Определение цели** через `get_team_info` и `get_channel_info`.
4. **Проверяемая публикация** через `create_post` только после подтверждения точного канала и текста.
5. **Помощь с настройкой** официального production endpoint Mattermost MCP.
6. **Документация на русском и английском**, публичные страницы конфиденциальности, условий и поддержки, тексты для marketplace и тестовые сценарии для ревью.

## Не входит в MVP

- Развёртывание, проксирование или повторная реализация MCP-сервера.
- Создание пользователей, команд или каналов.
- Изменение участников или прав.
- `create_post_as_user`, пароли или выдача себя за другого пользователя.
- Dev-инструменты Mattermost.
- Вложения и загрузка локальных файлов.
- Массовая или запланированная публикация.
- Фоновая синхронизация, индексация, аналитика или телеметрия.
- Пользовательский интерфейс ChatGPT.

## Критерии готовности

- Валидаторы плагина и skill проходят успешно.
- Автоматические тесты проходят без сети и учётных данных.
- Плагин устанавливается из локального marketplace Codex.
- Read-workflow указывают область источников и не выдумывают результаты.
- Write-workflow не может публиковать без явного подтверждения.
- Пакет для ревью содержит ровно пять позитивных и три негативных сценария.

## Стратегия публикации

Первая публичная заявка имеет тип **Skills only**. Для заявки “With MCP” нужен единый production URL под контролем издателя и подтверждение домена. Поддерживаемый Mattermost MCP endpoint уникален для каждого развёртывания и управляется администратором пользователя, поэтому проект не выдаёт его за собственный и не проксирует.
